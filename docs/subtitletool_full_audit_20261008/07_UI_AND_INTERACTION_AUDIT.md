# Windows Iced GUI 全屏幕与交互审计：建议实施规范

> 这是 V3.1 GUI 原文档 `04`、`05`、`35`、`36` 的整合整改建议，不是已经编译、运行或截图验收的 Iced 界面。产品为**已有字幕自动处理工具**，不提供逐句编辑、打轴、字幕创作。

## U-00 根布局与信息密度

建议 Windows 11 Fluent 风格但不强制 Fluent 原生控件；使用 Rust + Iced 原生窗口。UI 不必实现网页或 Tauri。主视图区四层：

1. **左侧固定功能导航**：转换、ASS HDR、FPS/时间、ASS→BDN/SUP、SUP调整、合并、批处理、字体/MKV；“视频辅助同步”作为二级工具或可选入口，不占主入口。
2. **中间工作区**：文件列表/摘要/核心参数，优先手动源和目标规格；支持拖入ASS/SRT/SUP/视频文件的类型检测。
3. **右侧或可折叠的多输出 Profile 面板**：每个Profile的格式、画布、色彩策略、渲染器、目标时间模式和输出路径，超窄时变抽屉。
4. **底部统一任务抽屉**：Queue/Running/Completed/PartialSuccess/Failed/Cancelled，显示子任务和每个产物结果。

屏幕宽度最小可用目标建议 1280px（**建议值非现有实现**），应额外在1366×768和150%、200%DPI检查内容能滚动而不遮挡“开始”按钮。不要写死像素宽度；先做响应式布局实验，再冻结组件尺寸。

## U-01 全局数据状态

- `AppState`只管理UI展示、路由、参数草稿、用户确认；不可直接保存Native渲染器句柄。
- `DraftOptions` 与 `Immutable JobSnapshot` 分离；点击执行时冻结所有参数，正在跑的任务不能因用户改下拉框而静默改变。
- 文件列表每个输入记录`source_path`、探测类型、编码、hash状态、验证状态、renderer需求；没有探测结果时显示“未知，待检查”而不是“已支持”。
- 参数来源必须可见：`手动 / 预设 / 从目标视频读取 / 默认`；同一字段手动设置的优先级高于辅助自动探测。
- 每个变更生成`ValidationSummary`：阻断（错误）、可继续（警告）、信息；“开始”按钮必须绑定与CLI相同的验证器。
- 失败、取消、部分成功是不同的结果，不能用一个绿色“完成”覆盖。

## U-02 文件导入和拖拽路由

- 拖ASS/SRT/VTT到转换区：产生待处理列表项，不能修改源文件。
- 拖SUP/PGS：先探测BD-PGS还是DVD/HD-DVD等异种同扩展，不支持就说明差异并提供引导。
- 拖MKV：显示“提取轨道/辅助识别目标片源”两种明确动作，不能擅自开始大体积转码。
- 拖目标视频：只读分辨率/fps/DAR/HDR元数据，**默认不给原字幕做时间变速**；单独按钮“建议同步”且必须由用户确认。
- 批量拖入目录：先扫描可读类型并列出命中数、跳过文件、大小估计，绝不在UI线程递归全盘。
- Windows Explorer路径可能为Unicode/UNC/长路径；`PathBuf`与进程参数数组应保留原义，不能通过字符串拼接shell。

## U-03 转换主页

| 控件 | 默认 | 用户可操作 | 拒绝/警告场景 | 执行模块 |
|---|---|---|---|---|
| 输入文件 | 空 | 多选/拖拽/删队列项 | 未支持格式/疑似混合编码 | `format-probe` |
| 输出格式 | 自动建议/用户选 | ASS/SRT/VTT/BDN/SUP能力矩阵 | ASS→SRT有样式损失 | `transform-plan` |
| 编码 | 原输入检测，输出UTF-8建议 | 原样/UTF8/BOM/指定 | 低置信度须确认 | `encoding` |
| 输出目录 | 源旁新目录建议 | 自选/保留相对目录 | 路径碰撞/只读/空间不足 | `commit-transaction` |
| 多输出 | 默认一个Profile | 增删/复制/排序 | duplicate path / impossible profile | `profile-planner` |
| 启动 | 禁用直到valid | 单文件/批量 | 阻断错误有详情弹层 | `job-scheduler` |

ASS→SRT“简化”必须列出具体损失：样式、位置、绘图、动画、重复/重叠事件和Inline markup语义；允许用户选择遇到绘图事件时“跳过并报告”而非错误输出乱码。

## U-04 ASS HDR工具

- 主操作：`输入ASS`、`变换模式`、`目标值`、`保存为新ASS`。默认不要求目标视频。
- 模式必须分开：`兼容百分比缩放`（编码字节乘法）、`线性光百分比`（sRGB EOTF/OETF）、`参考白近似`（需明确播放链假设且属于实验）。“33%”在不同模式结果不同，不共享一个描述。
- 同时调整ASS Style和内联颜色：`\c`、`\1c..\4c`、`\t(...)`；未知扩展要标注“未处理n处”并可查看。
- 默认不修改 alpha；用户能看“修改颜色token数”，输出保留原字幕事件/布局/时间码。若选择未知扩展需显式选择停下或保留并警告。
- HDR调光不是视频转码，界面禁止宣称“输出HDR视频”“保证203nit显示亮度”。

## U-05 FPS/时间页面

必须将下列控制设计为互斥操作：

- **Speed Change（改变播放速度）**：源视频FPS→目标视频FPS；需要用户确认“版本因加速/减速导致时长不同”。
- **Snap to Frame（时间点贴帧）**：目标FPS或实际VFR时间戳；保持影片时长，不自动把25→50变成2倍速。
- **Offset（整体平移）**：正负毫秒/帧，帧需绑定具体时间基。
- **Two Point（两点线性拟合）**：设置原/目标各2时间点，显示比例、偏移、误差与非线性片段不适用警告。
- **视频辅助**：ffprobe只提供可核验元数据；ALASS/音频辅助有“算法判断结果+确认应用到副本”。

转换前摘要显示原开始/结束时间、转换后起止和负时间/倒序/0长事件数量；负时间策略必须由用户明确选择。

## U-06 ASS→BDN/SUP页面

- **画布**：完整16:9预设1280×720/1920×1080/3840×2160；显示原ASS PlayRes单独信息，不“自动纠正”为16:9。
- **输出形式**：BDN+PNG、基础BD PGS、UHD BD PGS各有合法矩阵；对目标`3840×2160 + strict Blu-ray PGS`应阻止并解释，只允许非标准通用BDN/PNG路径。
- **renderer**：libass默认；探测到CSRI provider后才可以启用特殊特效；无法加载DLL时不自动偷偷切换而改变字幕效果。
- **采样**：普通/帧采样/高精度事件边界，预估中间图像大小；动态特效提示耗时。
- **验证**：结构验证、时间验证、buffer-model验证、真机验证必须是独立进度和能力层级。

## U-07 SUP调整页面

- 默认显示`不重编码位图`，可操作时间平移、FPS时长映射、窗口平移、palette-only亮度、Forced metadata等。
- resize/裁切如果需改ODS则明确告知“将重新编码图像”，不是宣称所有操作无损。
- `QuickPlayback`/`AuthoringAware`两种级别；蓝光严格检查未就绪时不显示“兼容通过”。
- 颜色处理提供Luma-only/Color-managed两条不同路径，彩色SUP不可悄悄按黑白luma逻辑完成。

## U-08 批量及多输出

- 每一输入对应多个 OutputProfile，树形展开任务：input→transform→render-group→output sinks。
- 共享结果界面仅作为性能提示；不能承诺1080/4K不同renderer真正“渲染一次”。
- 同名目标/NTFS大小写/非法保留名/路径过长/相同输入输出路径都提前预检。
- 预设变更不能影响进行中JobSnapshot；支持复制/批量勾选/禁用某个profile。
- 部分成功应列成功文件、失败文件、失败原因与仅重试失败项；输出生成后可单独“打开文件夹”。
- 取消后不要在已存在的正式目录里留下半套BDN XML/PNG。

## U-09 字体和MKV工具

- 字体“存在/匹配/字形覆盖/可嵌入/可再分发”五种状态互不等价；发现系统字体不意味着可以自动将其附到用户准备分享的MKV。
- 用户手动选择MKV内嵌轨道，并列出Track UID、Language、Default/Forced/SDH、附件；封装操作始终生成新文件，不能默默重写源MKV。
- subset 默认关闭或安全策略下使用；渲染差异不通过自动回退完整字体，但仍检查版权/许可。

## U-10 设置、运行时和错误

- `依赖健康`：libass构建版本、ffprobe/mkvmerge路径、外部滤镜位数/接口/导出/测试帧结果、DLL哈希、字体扫描状态。
- `用户安全提示`：第三方DLL可访问本机资源，独立host只能隔离崩溃，不能构成安全沙箱。
- `错误视图`：一个问题必须同时有StableErrorCode、用户中文解释、解决办法、调试详情（路径脱敏可复制）。
- `日志导出`：默认隐藏用户路径、文件名、ASS台词；调试日志可在用户明示下提高详细程度。

## U-11 Windows 交互验收矩阵

| Case | 输入/动作 | 预期 |
|---|---|---|
| UI-01 | 空列表单击开始 | 无任务创建；提示选择字幕 |
| UI-02 | 拖含中文路径和emoji的ASS | 文件被原样识别；结果可以写入中文路径 |
| UI-03 | 500字幕目录批量拖入 | UI持续响应；能取消扫描；逐项验证 |
| UI-04 | ASS HDR改203 nit但无播放链配置 | 不承诺物理亮度；实验模式要求确认 |
| UI-05 | 24→50只是帧重复不改变时长 | SpeedChange不自动触发 |
| UI-06 | 1080p BDN + UHD BD SUP | 输出任务合法组合显示，不混淆PGS画布 |
| UI-07 | 2160p Strict PGS | 阻断不合法组合，给出解释 |
| UI-08 | 32位DLL导入x64主程序 | 独立x86 host探测，不加载到GUI |
| UI-09 | 外部滤镜崩溃 | host崩溃，GUI显示失败且能继续其他任务 |
| UI-10 | 多输出相同文件名 | 预检冲突且不可覆盖源文件 |
| UI-11 | 多文件BDN写到一半断电 | 无已提交成功状态，重启可辨识staging残留 |
| UI-12 | 用户修改运行中配置 | 已启动JobSnapshot参数不变 |
| UI-13 | 1366×768、200%DPI | 开始/取消/输出面板可到达，滚动/键盘可用 |
| UI-14 | IME输入目录模板/自定义时间 | 候选文本与校验不冲突、无丢字符 |
| UI-15 | “仅位图不重编码”的SUP调整 | 输出ODS原始payload验证保持一致，报告时间/视觉变化 |

## UI开发顺序建议

`Windows Iced drag-drop PoC → 输入/格式探测 → Manual-first 参数页 → Profile验证与输出规划 → 无阻塞任务抽屉 → Renderer/颜色/PGS能力状态 → 异常恢复/键盘/DPI/E2E`。每一个可见按钮在功能矩阵中须有对应`Requirement ID → JobPlan字段 → 核心Stage → 验收Case`。
