# 渲染宿主与媒体探测可靠性修复

核对日期：2026-10-08。本轮继续处理现有 CLI 的可靠性，并完成上一轮非 C 盘缓存配置的构建核验。

## 修复内容

- Cargo 配置将链接器临时目录指向仓库 `target/tmp/`，但此前初始化脚本只创建自定义 Cargo 目标目录下的 `tmp/`。真实构建因此报 `LNK1104`。PowerShell 初始化和 Git Bash 入口现均先创建仓库 `target/tmp/`，构建已经通过。
- Cargo、vcpkg 下载与二进制缓存、sccache、ccache 和 pip 缓存使用非 C 盘目录。vcpkg 重试辅助现遵守 `VCPKG_DOWNLOADS`；PowerShell 验证入口先从实际 Git 安装目录寻找 Bash，支持本机 D 盘安装位置。
- renderer-host 接收线程此前使用无界队列，并在 EOF 后重复发送错误。现使用容量为一条消息的队列，EOF 和读取错误只发送一次，随后退出。接收线程还可能持有一条正在读取或等待入队的消息。
- IPC 解析在分配负载之前拒绝未知标签。非法 UTF-8 返回读取错误，避免用替换字符改变请求内容。
- ffprobe 超时此前只覆盖 stdout 读取，随后等待进程退出和 stderr 的步骤没有上限。现同时观察两个输出流与进程状态，统一执行截止时间。超时收尾分别限时等待两条读取线程，避免 stdout EOF 掩盖仍被孙进程持有的 stderr。

对应契约见渲染器规格与媒体探测规格。没有修改公开 CLI 参数或 IPC 版本。

## 行为验证

- `renderer-host`：13 项单元测试通过，其中新增真实子进程 EOF、截断后线程退出、非法 UTF-8 拒绝用例，并加强未知标签拒绝用例。5 项集成用例的测试目标退出 0；其中 3 项依赖 libass 的场景因缺少 DLL 提前返回，实际执行了 2 项 PE 位数与真实 host 拒绝加载测试。
- `media-probe`：23 项单元测试通过。新增 3 项真实进程测试，覆盖 stdout 提前关闭、两条输出管道提前关闭、父进程退出后孙进程继续持有 stderr。测试子进程使用同一个 Rust 测试可执行文件，通过原生管道制造生命周期场景，未模拟超时结果。
- 指定本机 ffprobe 并设置 `STK_REQUIRE_FFPROBE=1` 后，6 项真实工具测试全部通过，覆盖 SDR、HDR、4:3 画布、精确帧率、缺失输入、二进制身份与 PGS 容器时钟。
- 工作区单元与集成测试：55 个测试目标全部退出 0。该完整运行在上述新增修复之前启动；修复后的宿主与媒体探测代码随后分别重跑了适用测试。测试框架统计包含缺外部依赖时提前返回的用例，不将总数视为全部行为已经覆盖。
- 真实系统字体测试：7 项通过；本机系统字体目录有 759 个文件，与历史记录中的机器不同。
- 格式检查、workspace Clippy（拒绝警告）、20 个 crate 的串行 doctest 目标检查和最终 workspace release 构建均通过。本次 doctest 目标没有非零用例，不将目标通过数当作 doctest 行为覆盖数。

测试中使用的标准管道句柄和关闭操作按 Microsoft 的 [GetStdHandle](https://learn.microsoft.com/en-us/windows/console/getstdhandle) 与 [CloseHandle](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-closehandle) 文档核对。
