# 开发阶段与里程碑

> 2026-10-07 复核后调整。原计划把 GUI、CSRI、MKV、字体、PGS 和许可证探索全部放进 Phase 0，导致它们变成互不相关功能的共同前置条件。当前仓库已经有 CLI、任务引擎、libass、BDN 和 Basic PGS 代码，后续计划从现状继续，不按旧顺序重做。

## 执行原则

- 先修可靠性和真实渲染链，再扩展界面与适配器。
- 每阶段只设置与该阶段直接相关的退出条件。CSRI、x86、MKV 和 GUI 不阻塞 CLI 核心修复。
- 单元/集成行为优先由 Rust 测试证明。外部播放器、真盘语料和原生依赖只用于它们确实需要的互操作结论。
- Basic PGS 可交付不等于 Strict Blu-ray 合规。缺少裁决语料的规则保留为待决，不写成通过。

## Phase 0：当前可靠性收口

完成流式采样、renderer-host 实际渲染隔离、时间算术边界、PGS 计数字段拒绝、外部进程输出上限、输出事务恢复和文档入口修正。

**退出条件：** 相关 crate 回归测试通过；工作区测试和编译结果有本次日志；渲染依赖不可用时明确标记未覆盖。

## Phase 1：CLI 核心工作流

维护 ASS/SRT、时间/HDR/分辨率变换、格式探测、输出校验和批处理。新增功能前先确认 CLI 参数、数据模型、报告与输出事务行为一致。

**退出条件：** 每种用户可见变换都有正向与拒绝用例；输入和输出错误不覆盖原文件；批处理部分失败可定位到输入与 profile。

## Phase 2：渲染与 Basic 作者链

维护 libass → renderer-host → 增量事件规划 → BDN/PNG 或 Basic PGS 的共用前半链。修复采样、字体注入或帧传输时，使用真实 host 测试覆盖消息顺序、完整帧和失败路径。

**退出条件：** 可用 native DLL 时运行真渲染集成测试；无 DLL 时报告跳过，不把模拟 host 测试写成真实渲染证据。

## Phase 3：PGS 互操作裁决

先整理可合法使用的真盘 `.sup` 与播放器矩阵，再裁决调色板范围、图末标记、PCS 帧率字段和窗口平移语义。Advanced Author 与 Strict 验证器只在缓冲模型和兼容语料有证据后开展。

**退出条件：** 每个互操作结论有来源、样本哈希、播放器/解码器版本和可重复结果；没有样本时保持明确的未裁决状态。

## Phase 4：桌面界面 MVP

在 CLI 契约稳定后实现 Iced 文件选择、参数表单、任务队列、进度、取消和错误定位。界面复用现有 Job/Profile/报告模型，不另建一套转换语义。

**退出条件：** 长任务不阻塞 UI；取消与部分成功有端到端测试；界面输出与相同 CLI 参数一致。

## Phase 5：独立适配器

按用户需求分别评估字体子集、MKV 助手、CSRI provider、VapourSynth/AviSynth 和 x86 host。每项先做来源、许可、ABI 与维护成本核对，再决定实现或明确不支持。

**退出条件：** 每个适配器有独立 capability probe、真实依赖测试和许可证边界；一个适配器失败不影响 libass 基线。

## Phase 6：发布准备

完成 Windows 构建矩阵、portable/installer、签名、依赖清单、诊断信息脱敏、升级与卸载验证。只有被实际构建和验收的目标才列入发行支持矩阵。

## 可选研究

OCR、自动同步、Advanced PGS 和 legacy renderer 都是独立研究线，不列为 CLI MVP 的前置条件。每条研究线先交付可复现的技术结论，再决定是否进入正式产品范围。
