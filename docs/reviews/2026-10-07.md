# 全量审查与修正记录

审查日期：2026-10-07。审查依据包括当前 Rust 源码、工作区测试、产品规格、开发阶段、验收用例，以及 Git 中旧版 `docs/` 原文。旧文档迁移到 `docs/specs/`、`docs/planning/`、`docs/development/`、`docs/history/` 的本地改动予以保留。

## 主要发现与修正

### 代码与测试

- PGS author 原先需要保留整条渲染帧序列。现改为增量规划，只保留当前视觉 run 的裁剪补丁和最终事件；CLI 渲染逐帧送入规划器。
- CLI 渲染改由 `renderer-host` 执行。协议支持字体负载、逐帧 loss report 和大帧分块，并限制 host stderr 与单次会话字体总量。
- `media-probe` 限制 stdout 总量并只保留 stderr 尾部，避免外部进程无界输出占用内存。
- 时间解析和 PGS PCS/WDS 写入补齐溢出、负值、字段计数上限的拒绝行为及回归测试。
- 输出替换失败时尝试恢复旧目标；恢复失败会给出备份和临时文件位置。
- 字体交付集成测试不再随机挑选系统字体，改用与 ASS 请求匹配的 `arial.ttf`。内嵌字体真渲染测试在无 libass 时按 `STK_REQUIRE_LIBASS` 规则跳过或失败。
- 真实系统字体中存在 `OS/2.usWeightClass=5` 的 Fences 字体。测试曾错误要求 100–1000，现按 OpenType 1–1000 范围断言，避免把真实字体数据判为实现错误。
- 缺少或指向不存在文件的 libass DLL 时，CLI 现在先报告依赖错误，再决定是否扫描字体库；错误路径不再为了失败任务遍历整个 Windows 字体目录。
- renderer-host 的帧结果返回类型拆出具名类型别名，消除 Clippy `type_complexity` 警告。

### 原始文档与计划

- 旧 Phase 0 把 GUI、CSRI/x86、MKV、字体子集、PGS 与许可证探索绑成共同前置，造成无关工作互相阻塞。新阶段计划先收口现有 CLI、渲染隔离和输出可靠性，再分别裁决 PGS、GUI 与可选 adapter。
- 旧 CLI 文档把 GUI 可执行文件、preset、字体子集、MKV 及 GUI 命令重放写得像现有能力。现已按 `crates/cli/src/args.rs` 区分已实现命令、明确返回未实现错误的命令和未来契约。
- Windows 发布清单里的 x86 host、GUI、安装包、portable、签名和更新器属于未来目标，不是当前产物；文档已明确标注。
- Preset 示例包含尚不存在的 CLI/GUI 功能和 `special-auto` / `strict` 配置，现标注为目标草案。
- 字体 WBS 节点曾笼统写成 Windows 字体 API；现注明 DirectWrite 权威解析尚未实现。
- PGS 文档把结构目标容易读成已获设备验证。现列明 PCS 第 5 字节、palette range/matrix、ODS 图末标记仍需真盘和播放器语料裁决。
- 本机并行 doctest 会使多个 crate 报 `E0463`，同一工作区的 `cargo test --workspace --doc -j 1` 全部通过。开发指南现将行为测试和串行 doctest 分开，避免误把 rustdoc 并发问题记作源码失败。
- 历史状态和旧验证门阶继续保存在 `docs/history/`，不再作为当前状态或本轮验证结果。

## 仍需外部证据或后续决策

- 本机没有可用 libass DLL 时，真渲染集成场景不能声称通过。设置 `STK_REQUIRE_LIBASS=1` 可把跳过升级为失败。
- PGS 的图像字段互操作需要可合法使用的真盘 `.sup`、独立播放器/解码器及记录版本的样本矩阵。缺证据时保持待决，不以自家往返替代。
- GUI、DirectWrite resolver、font subset、MKV helper、CSRI provider 和发行安装链不属于本轮代码修复结果。
