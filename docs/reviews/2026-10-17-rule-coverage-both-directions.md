# 裁决：关掉 AK17 的「量出来的洞」——校验规则双向覆盖

- 日期：2026-10-17
- 相关：ISSUES AK17 / AK16（教训来源）、25 校验分层
- 相关工具：`tools/rule_coverage.py`
- 相关用例：`crates/validator/src/{ass.rs,decoder_model.rs}` 的 15 个新用例

---

## 1 这条不是“我觉得该测”，是量出来的

`tools/rule_coverage.py` 按 check id 把测试里的引用分成四类：

```
改前：19 该报单向 / 2 不该报单向 / 27 双向 / 15 未覆盖
改后：19 该报单向 / 7 不该报单向 / 37 双向 /  0 未覆盖
```

### 为什么必须成对写

- **只有“该报”的用例** → 规则算**偏严**也能长期活着
  （例子正是 AK16 的 `PGS.TML.05`：把 fps 当秒数换算，误伤合法文件，
  而它唯一的用例在 bug 下照样报 warning —— **为错误的理由通过**）。
- **只有“不该报”的用例** → 规则**失效**同样没人知道。

所以本次补的 15 条**每条都有正反两面**。

## 2 补的过程里，我的假设错了五次（产品全是对的）

造 fixture 时我按“看起来该这样”写了五个，实测**全不报**。
每次追下去都是我的假设错。这五次都写进了注释。

### 2.1 `ASS.STR.03` 的 Styles 分支走不到

我以为：删掉 Styles 的 `Format:` 行 → 报 03。
实测：报的是 `ASS.STR.04`（`format_source = RepeatedHeader`）。

追到 `codec-ass` 才明白字段表有**四档来源**
（`FormatLine` / `RepeatedHeader` / `Fallback` / `None`），
而 `needs_format()` 的 Styles/Events **总会被填上一种** ——
`s.format` 永远不空。`FormatSource::None` 只出现在
`SectionKind::Unknown` 的默认表上，那种段不走这个分支。

**结论**：强造一个能触发它的输入需要打破解析器的不变式，
那测的就是**假想中的代码**而不是真实行为。
所以用例改成锁**实际成立的那件事**，并把“03 的 Styles 分支疑似不可达”
记在注释里 —— 那是它在盘点表上长期未覆盖的**真实原因**。

### 2.2 `SRT.EVT.03` 的标题比实际条件宽

我以为：“非整拍的时间”就报。
实测：不报。读 `to_pts_ticks` 才看清它是
`mul(90_000).round_i64()` —— **会四舍五入**，普通值永远不出错。

真实条件只有两件事：**负时间**、**溢出 33bit 上限**。
所以这条的真实含义是“**这个时间不是合法 PTS**”，
而不是它的标题说的“无法表示为毫秒”。

### 2.3 `PGS.DEC.01` 方向写反了

条件（读代码）：`s.pts > pcs_pts` —— 段的 PTS **晚于**该集 PCS。
我造的是“早于”，因为想当然认为“PCS 之前的段不可能”。
实际上 PCS 带的本来就是本集**最高**呈现时刻。

### 2.4 `PGS.DEC.05` 名字骗了我

按名字以为是“段类型顺序不合规”（把 ODS 摆到 PCS 前面）。
实测不报。真实条件扫的是
`segments[i].dts < segments[i-1].dts` —— **整个流上 DTS 必须单调不减**。

名字里的“顺序”指的是**时间上的顺序**，不是类型顺序。

### 2.5 我自己拼的“干净显示集”不干净

第一版 `inv_clean()` 是我凭直觉写的，一上来就报 `PGS.DEC.01`。
照着本模块已有的 `clean_set(base)` 抄才对 ——
而这件事**本身就是这五条不变式值得写用例的理由**。

## 3 另一处问题：测了，但量不出来

第一版断言我写成：

```rust
assert!(rules_of(&s).contains(&"PGS.DEC.01"));
```

**断言是对的**，用例也确实覆盖了。但 `rule_coverage.py` 扫的是
`<报告>.has_check("<id>")` 这个**方法调用**写法 ——
自由函数 `has_check(&segs, id)` 它看不见。

于是盘点表上这五条**依旧写着“一次都没提到”**。

**那比没测更坏**：下一个人会照着过期的事实重复劳动。
改成：

```rust
assert!(report_of(&s).has_check("PGS.DEC.01"));
```

工具数得到，而那本来就是 `ValidationReport` 自带的 API。
（中间还试过叫 `has_check` 的自由函数 —— 形似而神不似，
工具仍然不认。最后是**返回报告本身**才解决。）

**教训**：断言正确与**事实可测量**是两件事。
当某个工具负责告诉别人“还缺什么”时，让它数得到本身就是需求的一部分。

  真实 SUP 上的那套在 `decoder_model_real.rs`，两者不能互相代替。
